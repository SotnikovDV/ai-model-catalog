# Security Policy

## Reporting a Vulnerability

Если вы нашли уязвимость в AI Model Catalog, опишите её в приватном сообщении
автору репозитория (GitHub Security Advisory или личное сообщение maintainer).
Не публикуйте PoC и секреты в Issues.

Ожидаемый ответ: подтверждение в разумный срок и план исправления для
подтверждённых проблем с высоким приоритетом.

## Deployment checklist

Перед публичным или сетевым деплоем:

1. Задайте `ADMIN_PASSWORD` и `SESSION_SECRET` в `.env` (не оставляйте пустыми).
2. Используйте HTTPS (reverse proxy).
3. Не коммитьте `.env`, `data/`, `backups/` — они в `.gitignore`.
4. После случайной утечки ключей — **ротируйте** API-ключи провайдеров и AI.
5. `GET /health` публичен намеренно (мониторинг); не отдавайте через него секреты.

## Auth model (кратко)

- При пустом `ADMIN_PASSWORD` защита отключена (только для локальной разработки).
- При заданном пароле: каталог на чтение открыт; админка, CRUD моделей, чат,
  AI-ассистент, sync/evaluate и смена ключей — только после входа (сессия или HTTP Basic).
